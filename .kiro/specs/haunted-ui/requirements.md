# Haunted UI: requirements

Coherent, polished, themed product experience. BOB is a friendly ghost. EARS IDs `UI-n`.

## Requirements
- **UI-1** THE System SHALL provide panels for Overview, Brain, Ghost Text, Selection Actions, Dictation and About.
- **UI-2** THE System SHALL ship a dark default theme and an optional light "daylight" theme, both driven by CSS variables.
- **UI-3** THE System SHALL show the BOB orb with states: idle, listening, thinking, haunting (suggestion visible), error.
- **UI-4** WHEN a first run is detected, THE System SHALL guide the user through Accessibility, Microphone and model setup with clear, playful copy.
- **UI-5** THE System SHALL run from the menu bar; closing the window SHALL hide it, not quit.
- **UI-6** WHERE the OS requests reduced motion, THE System SHALL disable non-essential animation.
- **UI-7** THE System SHALL meet WCAG AA text contrast in both themes.
- **UI-8** THE System SHALL make all controls keyboard-operable with visible focus and accessible names.
- **UI-9** THE System SHALL show brain status (local/cloud label, latency) wherever a brain is selected.
- **UI-10** THE chip and action menu rendered natively SHALL use the same palette as the web UI tokens.
- **UI-11** THE System SHALL NOT use third-party trademarks or copyrighted audio.
